Resumen

El presente informe documenta el desarrollo e implementación de una mejora sobre el sistema ERPNext, consistente en un módulo de análisis predictivo con inteligencia artificial. El módulo permite pronosticar la demanda futura de productos, detectar posibles quiebres de stock y sugerir cantidades óptimas de compra, integrándose con los módulos nativos de ventas, almacén y compras de ERPNext.

La solución fue desarrollada como una extensión del aplicativo ERPNext, utilizando el framework Frappe, Python y librerías de machine learning como scikit-learn, pandas y numpy. Se implementaron cuatro DocTypes principales: Configuración de Predicciones, Ejecución de Predicción, Predicción de Producto y Predicción Diaria. Además, se crearon un workspace exclusivo, un reporte de precisión y una tarea programada para ejecución diaria automática.

El despliegue se realizó mediante Docker Compose, logrando que el módulo esté disponible en la interfaz del Desk de ERPNext. Se incluyeron datos de prueba peruanos reales: una empresa, 30 productos tecnológicos, 15 clientes, 5 proveedores y 443 facturas de venta, lo que permitió validar el funcionamiento del predictor con información concreta.

1. Introducción

1.1. Planteamiento del problema

Las pequeñas y medianas empresas que gestionan inventarios enfrentan constantemente el desafío de equilibrar el stock disponible con la demanda esperada. El exceso de inventario genera costos de almacenamiento elevados y riesgo de obsolescencia, mientras que la falta de stock implica pérdida de ventas y clientes insatisfechos. ERPNext carece de forma nativa de un mecanismo predictivo con IA para solventar esto de manera inteligente.

1.2. Justificación

Al aplicar modelos de machine learning sobre el historial de ventas, es posible estimar de forma certera la demanda futura y reducir quiebres de stock:

  • Anticipar demanda en períodos futuros.
  • Estimar la fecha exacta de agotamiento de stock.
  • Sugerir compras óptimas basadas en seguridad.
  • Eliminar decisiones basadas puramente en intuición.

1.3. Objetivos

Objetivo General:

Desarrollar e integrar un módulo de análisis predictivo con inteligencia artificial en ERPNext para pronosticar ventas, detectar quiebres de stock y sugerir compras óptimas.

Objetivos Específicos:

  1. Implementar un motor de predicción con Random Forest y regresión lineal.
  2. Crear los DocTypes requeridos para el almacenamiento de datos.
  3. Diseñar un workspace y reporte dinámico de precisión.
  4. Desplegar en un entorno funcional y reproducible de Docker.

3.3. Diseño e Interfaz de Datos

El flujo recopila el historial desde Sales Invoice Item y el stock actual en tiempo real para generar las predicciones.

Prediction Settings Configuración general: modelo seleccionado, días mínimos de historial e inventario de seguridad.
Prediction Run Bitácora e historial de ejecuciones con estatus, fecha y cantidad de productos procesados.

Prediction Day Tabla hija interna con el desglose pormenorizado día por día de los volúmenes esperados.

Motor de Predicción (utils.py)

def run_prediction_for_item(item_code: str, prediction_days: int = 30, model_type: str = "Random Forest", safety_stock_days: int = 7):
    history = get_sales_history(item_code)
    if len(history) < min_history_days: return None
    
    dates = [getdate(row.posting_date) for row in history]
    quantities = [flt(row.qty) for row in history]
    
    X, y = build_features(dates, quantities)
    model = train_model(X, y, model_type)
    predictions = predict_future(model, dates[-1], prediction_days)
    
    return {
        "item": item_code, 
        "predicted_total": round(sum(predictions), 2),
        "suggested_purchase_quantity": calculate_suggestion(predictions)
    }

5.5. Diagnóstico del Margen de Error Alto:

El error del 306.9% se atribuye a: 1) Características temporales muy básicas en el entrenamiento. 2) Fuertes picos estacionales acumulativos que desvían los árboles del bosque aleatorio. 3) Efecto bola de nieve por agregación agregada de desviaciones diarias consecutivas.

Conclusiones

  • Integración transparente del módulo de IA sin alterar código nativo del ERPNext.
  • Automatización completa mediante hooks diarios nativos de Frappe Scheduler.
  • Portabilidad integral garantizada gracias a contenedores Docker parametrizados.
  • Validación exitosa del flujo completo empleando un set robusto de 443 facturas peruanas reales.

Recomendaciones

  • Migrar hacia algoritmos robustos de series de tiempo complejas como Prophet o SARIMA.
  • Incorporar gráficos analíticos de tendencias y dispersión en la UI del Workspace de Frappe.
  • Habilitar la generación automática de Órdenes de Compra vinculadas a la cantidad sugerida de manera directa.
